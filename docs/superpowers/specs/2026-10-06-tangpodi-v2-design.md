# ตังค์พอดี v2 — Design Spec

วันที่: 2026-10-06 · สถานะ: รอผู้ใช้ตรวจ

## เป้าหมาย

แอปเดิมใช้งานยากและมีฟีเจอร์น้อยเมื่อเทียบกับคู่แข่ง v2 ต้องทำให้:

1. **ใช้ง่ายขึ้น**: จดรายการได้ในไม่กี่แตะ เมนูน้อยลง เห็นตัวเลขสำคัญตัวเดียวชัด ๆ
2. **หมูเป็น Guide** ตลอดการใช้งาน ไม่ใช่แค่ป๊อปอัปครั้งเดียว
3. **ออมเงินกับเพื่อน**: กระปุกร่วม เชิญเพื่อนได้
4. **ฟีเจอร์ระดับคู่แข่ง**: สแกนสลิป, แชร์สลิปเข้าแอป, หารบิล, หมูสรุปรายเดือน, รายการประจำ

## ข้อจำกัดและข้อตกลง

- ยังเป็นเว็บแอป React + Vite + PWA บน GitHub Pages (ไม่มีเซิร์ฟเวอร์ของเราเอง)
- **Local-first**: ข้อมูลส่วนตัว (รายรับจ่าย บิล หนี้ รายการประจำ) อยู่ใน IndexedDB ในเครื่องเหมือนเดิม **ไม่ถูกอัปโหลด**
- Supabase ใช้เฉพาะฟีเจอร์ที่ต้องแชร์ข้ามคน (กระปุกเพื่อน, หารบิล) ล็อกอินเป็นทางเลือก
- แอปไม่เชื่อมธนาคาร ทุกอย่างเป็นการ **จดบันทึก** ไม่โอนเงินจริง
- สแกนสลิปอ่านข้อมูลมาเติมฟอร์ม **ไม่รับรองว่าสลิปจริงหรือปลอม** (ต้องใช้ API ธนาคาร/บริการเสียเงิน ไม่อยู่ในขอบเขต)
- ภาษาไทยทั้งหมด, ไม่ใช้ emoji เป็นไอคอน (ใช้ Lucide), ปฏิบัติตาม `DESIGN.md` ยกเว้นที่ระบุว่าแก้ในเอกสารนี้
- ต้องมีผู้ใช้สร้างโปรเจกต์ Supabase เอง (ฟรี) และส่ง URL + anon key ให้ (ค่าสาธารณะ) ความปลอดภัยพึ่ง Row Level Security
- โปรเจกต์ Supabase ฟรีจะ pause หลังไม่มีการใช้งาน 1 สัปดาห์ (กด resume ได้ ข้อมูลไม่หาย)

## แผนส่งมอบ 3 รอบ (แต่ละรอบ = spec ย่อย → plan → implement → deploy)

| รอบ | ขอบเขต | พึ่ง Supabase |
|---|---|---|
| **1** | UI ใหม่ + หมู Guide + รายการประจำ + หมูสรุปรายเดือน | ไม่ |
| **2** | ล็อกอิน + กระปุกกับเพื่อน + เชิญเพื่อน + หารบิล | ใช่ |
| **3** | สแกนสลิป + แชร์สลิปเข้าแอป (Web Share Target) | ไม่ (หารบิลดึงผลสแกนได้ภายหลัง) |

หลัง spec นี้ได้รับอนุมัติ จะทำ plan ของ **รอบ 1 เท่านั้น** รอบ 2–3 มี spec ย่อยของตัวเองเมื่อถึงเวลา เพราะรายละเอียดจะเปลี่ยนตามที่เรียนรู้จากรอบก่อน

## รอบ 1: UI ใหม่ + หมู Guide

### โครงสร้างนำทาง

แท็บล่าง 4 อัน + ปุ่ม **+** ลอยตรงกลาง (เดสก์ท็อป: sidebar เดิมแต่ 4 รายการ)

| แท็บ | เนื้อหา | มาจากหน้าเดิม |
|---|---|---|
| หน้าแรก | "วันนี้ใช้ได้อีก ฿xxx" เป็นตัวเลขใหญ่สุด, หมูพูดบริบท 1 ข้อความ, บิลใกล้ถึง, สรุปสัปดาห์/เดือน | ภาพรวม |
| รายการ | สลับ มุมมอง ลิสต์ / ปฏิทิน ในหน้าเดียว, ค้นหา/กรอง | รายการ + ปฏิทิน |
| กระปุก | กระปุกส่วนตัว (รอบ 2 เพิ่มส่วน "กับเพื่อน") | กระปุก |
| เพิ่มเติม | เครื่องมือ (ค่าน้ำไฟ จำลองรายจ่าย สีมงคล), รายการประจำ, ตั้งค่า, สำรอง/นำเข้า | เครื่องมือ + ตั้งค่า |

ปุ่ม **+**: เปิด bottom sheet เลือก จ่าย / รับ / (รอบ 3: สแกนสลิป) ฟอร์มจ่ายเหลือช่องบังคับน้อยที่สุด (จำนวนเงิน + หมวด) ที่เหลือพับเป็น "รายละเอียดเพิ่มเติม"

Route hash เดิม (`#/overview` ฯลฯ) ต้อง redirect ไปหน้าใหม่ ไม่ทำให้ลิงก์เก่าพัง

### หมู Guide

คอมโพเนนต์ `Piggy` เดียว (ภาพ + ฟองคำพูด) ใช้ 3 โหมด:

1. **ทัวร์ครั้งแรก (Coach marks)**: ไฮไลต์ (spotlight) องค์ประกอบจริงบนหน้าจอทีละขั้น: ตัวเลขใช้ได้อีก → ปุ่ม + → แท็บกระปุก → แท็บเพิ่มเติม จบด้วยให้ลงมือจดรายการแรกจริง ข้ามได้ทุกขั้น สถานะค้างข้ามการรีโหลดจนเสร็จหรือข้าม (กลไก `tangpodi-onboarding-pending` เดิม) เปิดซ้ำได้จาก เพิ่มเติม → "ให้หมูพาเที่ยวอีกครั้ง"
2. **หมูประจำหน้า**: ปุ่มหมูเล็กมุมหัวหน้า กดแล้วอธิบายหน้านั้นสั้น ๆ + empty state ที่หมูชวนทำสิ่งแรกของหน้านั้น
3. **หมูทักตามบริบท**: กฎคำนวณในเครื่อง (ไม่ใช้ AI) เช่น งบเหลือน้อยกว่า X%, บิลครบกำหนดใน 3 วัน, กระปุกถึงเป้า ข้อความละ 1 ข้อ ปิดได้ จำว่าปิดอะไรแล้ว ไม่ทักเรื่องเดิมซ้ำภายใน 24 ชม. ตั้งปิดการทักทั้งหมดได้

ข้อความทั้งหมดของหมูอยู่ในไฟล์เดียว (`src/lib/piggyScript.ts`) เพื่อแก้คำง่ายและทดสอบได้

**เปลี่ยนแปลงใน DESIGN.md:** ข้อห้าม "invented mascot" ถูกแทนด้วย: หมูเป็นตัวนำทางที่ผู้ใช้ขอ ต้องไม่ใช้ปกปิดหน้าว่างเปล่า ไม่ขึ้นบังตัวเลขเงิน ไม่เกิน 1 ข้อความพร้อมกัน ไม่ทำเป็นเกม (ไม่มีแต้ม/ระดับ/streak)

### หมูสรุปรายเดือน + รายการประจำ (ในรอบ 1)

- **รายการประจำ**: ผู้ใช้ตั้งชื่อ ยอด หมวด ความถี่ (รายเดือน/สัปดาห์) วันที่ ระบบสร้างรายการให้เองเมื่อถึงกำหนดตอนเปิดแอป (ไม่มี background job; ย้อนสร้างวันที่พลาดไปแต่ทำเครื่องหมายว่า "สร้างอัตโนมัติ" แก้/ลบได้) ต้องกันสร้างซ้ำ (idempotent ด้วย key รายการประจำ+วันที่)
- **สรุปรายเดือน**: คำนวณจาก FinanceData เทียบเดือนก่อน: หมวดที่เพิ่มขึ้น/ลดลงมากสุด ประมาณวันที่งบจะหมด ประมาณผลต่อกระปุกเป้าหมาย แสดงเป็นการ์ดในหน้าแรกต้นเดือน + ในหมูทัก ใช้ตัวเลขจริงเท่านั้น ไม่เดา

### โครงสร้างโค้ด (รอบ 1)

- แยก `pages.tsx` (385 บรรทัด) เป็นไฟล์ตามหน้าใน `src/pages/`
- `src/components/piggy/` : `Piggy.tsx`, `CoachMarks.tsx`, `PageHelp.tsx`
- `src/lib/piggyScript.ts`, `src/lib/piggyHints.ts` (กฎทัก), `src/lib/recurring.ts`, `src/lib/monthlySummary.ts` ทุกอันเป็นฟังก์ชันบริสุทธิ์ มี unit test (vitest)
- `FinanceData` เพิ่ม `recurring[]` และ `piggy: { dismissed: Record<string, string>, hintsEnabled }` พร้อม migration ใน `data.ts` ให้ข้อมูลเดิมโหลดได้ ไม่สูญหาย และ backup เวอร์ชันเก่าต้องนำเข้าได้
- CSS: ใช้โทเคนใน `src/index.css` เดิม

### การทดสอบ (รอบ 1)

- Unit: recurring (ไม่สร้างซ้ำ, ย้อนหลัง, สิ้นเดือน 29–31), monthlySummary, piggyHints (เงื่อนไข + cooldown), migration ข้อมูลเก่า, backup เก่านำเข้าได้
- Component: ทัวร์ (ข้าม/ค้างข้าม reload/จบ), ปุ่ม + และฟอร์ม, redirect hash เก่า
- ตรวจจริงในเบราว์เซอร์มือถือ (375px) และเดสก์ท็อป ทั้งโหมดสว่าง/มืด และ `prefers-reduced-motion`
- `pnpm test`, `pnpm lint`, `pnpm build` ผ่านก่อน deploy

## รอบ 2 (ระดับออกแบบ รายละเอียดทำใน spec ย่อย)

- **ล็อกอิน**: Supabase Auth ด้วย Google (ทางเลือก) ใช้แอปแบบเดิมได้โดยไม่ล็อกอิน
- **ตาราง**: `profiles`, `shared_jars`, `jar_members(jar_id, user_id, role)`, `jar_entries(jar_id, user_id, amount, kind, note, created_at)`, `jar_invites(code, jar_id, expires_at)`; `bills` + `bill_items` + `bill_shares` สำหรับหารบิล
- **RLS**: อ่านได้เฉพาะสมาชิกของกระปุก; เพิ่ม/แก้/ลบ entry ได้เฉพาะของตัวเอง; owner ลบสมาชิก/กระปุกได้; join ผ่านฟังก์ชัน RPC ที่ตรวจรหัสเชิญและวันหมดอายุเท่านั้น (ไม่ให้ select ตาราง invites ตรง ๆ)
- **เชิญ**: ลิงก์ `#/join/CODE` + รหัส 6 ตัว ปุ่มแชร์ผ่าน Web Share API (LINE ฯลฯ)
- **เรียลไทม์**: Supabase Realtime บนกระปุกที่เปิดอยู่
- **ออฟไลน์**: กระปุกเพื่อนต้องออนไลน์เพื่อเขียน แสดงสถานะชัดเจน ไม่ทำ offline queue ในรอบนี้
- **หารบิล**: สร้างบิล เพิ่มรายการ ติ๊กว่าใครกิน คำนวณยอดต่อคนแบบจำนวนเต็มสตางค์ (กันเศษปัดผิด) แสดงใครติดใคร + QR PromptPay (สร้างในเครื่อง) ที่ผู้ใช้ใส่เลข PromptPay ของตัวเอง
- **ความเป็นส่วนตัว**: สมาชิกเห็นเฉพาะชื่อ/รูป Google และรายการในกระปุกนั้น ผู้ใช้ลบบัญชี/ออกจากกระปุกได้
- ต้องมีคู่มือตั้งค่า Supabase (SQL migration, เปิด Google provider, redirect URL ของ GitHub Pages) และผู้ใช้เป็นคนสร้างโปรเจกต์

## รอบ 3 (ระดับออกแบบ)

- **สแกนสลิป**: เลือก/ถ่ายรูป → ย่อ/ปรับภาพในเครื่อง → อ่าน QR (เลขอ้างอิงธุรกรรม สำหรับกันจดซ้ำ) + OCR ภาษาไทย (Tesseract.js โหลดแบบ lazy เฉพาะตอนใช้ ไม่ทำให้โหลดแอปช้า และ cache ออฟไลน์ผ่าน service worker) → แยกยอด/วันที่/ผู้รับ/ธนาคารด้วย parser ที่ทดสอบกับสลิปตัวอย่าง → เติมฟอร์มรายจ่าย **ให้ผู้ใช้ตรวจและแก้ก่อนบันทึกเสมอ** ถ้าอ่านไม่ออกบอกตรง ๆ ให้กรอกเอง
- ออกแบบ interface `SlipReader` ให้สลับเป็น AI vision (Supabase Edge Function) ได้ภายหลังโดยไม่รื้อ UI
- **แชร์สลิปเข้าแอป**: `share_target` ใน manifest (PWA) รับรูปจากแอปธนาคาร → หน้าสแกน หมายเหตุ: ใช้ได้กับ Android Chrome เมื่อติดตั้ง PWA; iOS Safari ไม่รองรับ share target ให้ใช้ปุ่มเลือกรูปแทน (บอกผู้ใช้ในแอป)
- ภาพสลิปไม่ถูกเก็บถาวรโดยค่าเริ่มต้น เก็บแค่ข้อมูลที่ผู้ใช้ยืนยัน

## นอกขอบเขต

ตรวจสอบสลิปจริง/ปลอม, เชื่อมบัญชีธนาคาร, โอนเงินจริงในแอป, แต้ม/อันดับ/streak, แจ้งเตือน push, offline write queue ของกระปุกเพื่อน

## ความเสี่ยง

| ความเสี่ยง | แนวทาง |
|---|---|
| OCR ไทยบนสลิปแม่นไม่พอ | บังคับตรวจก่อนบันทึก, parser รองรับหลายธนาคารเริ่มจาก 3–4 ธนาคารยอดนิยม, ออกแบบให้สลับเป็น AI ได้ |
| RLS ตั้งผิดทำให้ข้อมูลรั่ว | เขียน policy + ชุดทดสอบ SQL ก่อนใช้งาน, ไม่เปิด select ตาราง invites |
| ขอบเขตใหญ่ | แบ่ง 3 รอบ, รอบ 1 ใช้งานได้เองโดยไม่ต้องรอ Supabase |
| iOS ไม่รองรับ share target | บอกชัดเจน มีทางเลือกเลือกรูปเอง |
| โครงการ Supabase ฟรีถูก pause | แสดงข้อความเมื่อเชื่อมต่อไม่ได้ ฟีเจอร์ส่วนตัวไม่ได้รับผลกระทบ |
